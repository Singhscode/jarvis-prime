# Version 0.6.0 — Client Management

## Summary

Phase 3 delivers the smallest approved Client Management capability: authenticated users can convert an active CRM lead into a client and manage that client’s contacts. The conversion preserves CRM history and is atomic.

## Added

- Owner-scoped `crm_clients` records.
- Eight `/api/crm` client and client-contact endpoints.
- Client associations on existing CRM contacts and CRM leads.
- Atomic CRM Lead → Client conversion.

## Improved

- Converted leads no longer appear in active CRM lead lists.
- Deleting a client safely clears its associations; the preserved lead becomes active again.

## Security

All endpoints use the existing JWT middleware and scope reads and mutations to `owner_user_id`. The conversion path verifies ownership before calling the database function.

## Database Changes

Migration `20260715000005_create_client_management.sql` adds `crm_clients`, nullable `client_id` columns on `contacts` and `crm_leads`, focused indexes, and `convert_crm_lead_to_client`.

## API Changes

Added `GET`, `POST`, `PATCH`, and `DELETE` for `/clients`, plus `GET`, `POST`, `PATCH`, and `DELETE` for `/clients/:clientId/contacts`. No client detail endpoint or generic CRUD API was added.

## Tests

Local migration reset passed through `20260715000005`. The final suite passed: API 39/39 and ICP scorer 16/16. Root lint, build, `npm ci --dry-run`, diagnostics, and `git diff --check` also passed.

## Architecture Decisions

The release reuses the existing CRM module and contacts table, adds only `crm_clients`, and uses a dedicated PostgreSQL transactional function solely because the Supabase JavaScript client has no application-level transactions. It intentionally avoids generic CRUD, generic repositories, and unnecessary abstractions.

## Technical Debt

No Phase 3 technical debt was introduced. The root dependency audit retains two moderate PostCSS findings pinned inside Next.js’s dependency graph; no downgrade or `node_modules` patch is appropriate. Remote Supabase migration reconciliation remains deliberately separate.

## Known Limitations

Phase 3 excludes projects, tasks, contracts, billing, client portal features, client detail retrieval, and workflow automation. Those are outside this phase’s approved scope.

## Upgrade Notes

For local development, run `npm run db:reset` with Docker Desktop running. Do not apply migrations to a remote project until it is linked, its migration status is reviewed, and explicit approval is given.
