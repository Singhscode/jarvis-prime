# Version 0.7.0 — Project Management

## Summary
Phase 4 completes the Website Lead → CRM Lead → Client → Project workflow with minimal, authenticated project management.

## Added
- Owner-scoped project listing, creation, rename, and deletion.
- Required Client → Project relationship.
- Client deletion protection while projects exist.

## Improved
CRM clients now preserve project integrity by returning `409 CLIENT_HAS_PROJECTS` when deletion would orphan projects.

## Database Changes
Migration `20260715000006_create_project_management.sql` adds `crm_projects`, one owner index, a required client foreign key, and RLS enablement.

## API Changes
Added `GET` and `POST /api/projects`, plus `PATCH` and `DELETE /api/projects/:id`. No project detail or versioned duplicate endpoint was added.

## Security
All project endpoints use existing JWT authentication. Every project query is owner-scoped, and creation verifies CRM client ownership.

## Tests
API tests pass 41/41 and ICP scorer tests pass 16/16. The two Phase 4 tests cover unsupported fields and whitespace-only names. Lint, build, diagnostics, and diff checks pass.

## Architecture Decisions
The release uses one `crm_projects` table and explicit methods in the existing CRM repository, service, and route files. It adds no generic CRUD, generic repository, or unnecessary abstraction. Projects remain separate from Tasks.

## Technical Debt
No Phase 4 implementation debt was introduced. The root audit retains two moderate PostCSS findings within Next.js’s dependency graph.

## Known Limitations
Phase 4 intentionally excludes project detail retrieval, status, dates, tasks, members, files, comments, billing, automation, analytics, and AI.

## Upgrade Notes
Apply the canonical migration through the approved database process. Do not run a local database reset against data that must be preserved. Remote Supabase reconciliation remains separately controlled.
